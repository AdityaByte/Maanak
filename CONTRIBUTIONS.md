# Contribution Guidelines

Check this guide before contributing to the project.

### Step 1: Create an Issue

Create an issue describing what you want to work on.

If an issue already exists, ask the project leader to assign it to you.

### Step 2: Assign the Issue

If you created the issue yourself, assign it to yourself.

Make sure you have an issue assigned to you before starting development.

### Step 3: Create a Branch

Create a separate branch for the issue you are working on.

For example:

`feature/authentication`

Other examples:

`feature/rag-pipeline`

`feature/dashboard`

`fix/login-error`

The branch should be related to the issue you are working on.

### Step 4: Work on Your Branch

Make your changes only on your assigned branch.

Do not modify or overwrite code that another contributor is currently working on.

Keep your changes focused on the issue assigned to you.

### Step 5: Push Your Changes

Push your branch to GitHub:

`git push origin feature/authentication`

Do **not** push directly to the `main` branch.

### Step 6: Create a Pull Request

Once your work is complete, create a Pull Request from your branch to `main`.

The code will then be reviewed by the project leader or another assigned reviewer.

### Step 7: Review and Merge

After review:

- If the code is approved, it will be merged into `main`.
- If changes are requested, make the required changes on the same branch and push them again.
- Once the changes are approved, the Pull Request will be merged.

## Important

> **Never push directly to `main`.**

Always work through:

**Issue → Branch → Development → Push → Pull Request → Review → Merge**
